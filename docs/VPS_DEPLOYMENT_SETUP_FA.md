# راهنمای آماده‌سازی و استقرار VPS پروژه E.Y.T

این راهنما برای استقرار کنترل‌شده مخزن `eytcar-creator/Eyt-erp` است. وجود این راهنما یا موفقیت CI به‌تنهایی به معنی استقرار واقعی نیست.

## وضعیت و تصمیم معماری

- سایت اصلی `eytparts.ir` را فعلاً روی هاست فعلی نگه دارید؛ رکورد دامنه اصلی را بدون برنامه مهاجرت تغییر ندهید.
- سرویس ERP و کاتالوگ را روی VPS لینوکسی مستقل اجرا کنید.
- اطلاعات قبلی پروژه نشان می‌دهد هاست Linux10 اشتراکی بوده است. هاست اشتراکی را VPS فرض نکنید و روی آن Docker را هدف استقرار قرار ندهید.
- پیش از خرید VPS جدید، در پنل IranServer بررسی کنید آیا VPS فعالی وجود دارد یا فقط هاست اشتراکی. اندازه VPS باید بر اساس سرویس موجود، منابع و قیمت واقعی انتخاب شود.
- PostgreSQL و پورت‌های داخلی برنامه نباید مستقیماً روی اینترنت منتشر شوند. Compose آن‌ها را روی loopback می‌بندد.

## پیش‌نیازهای VPS

- Ubuntu Server 24.04 LTS یا نسخه پشتیبانی‌شده مشابه.
- دسترسی SSH مدیریتی از راه امن.
- Docker Engine و Docker Compose plugin نصب‌شده.
- `rsync` و `curl` نصب‌شده.
- کاربر اختصاصی استقرار با دسترسی به Docker و مسیر `/opt/eyt-erp`.
- فضای ذخیره‌سازی و RAM کافی، به‌علاوه فضای جداگانه برای نسخه‌های پشتیبان.
- دیواره آتش: SSH فقط از مبدأهای مجاز؛ پورت‌های 80 و 443 برای reverse proxy. پورت 5432 و پورت‌های داخلی API/کاتالوگ را عمومی نکنید.

## آماده‌سازی سرور

دستورات زیر را از کنسول VPS با حساب مدیریتی اجرا کنید. نام کاربر استقرار در این نمونه `eytdeploy` است:

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-v2 rsync curl
sudo systemctl enable --now docker
sudo useradd --create-home --shell /bin/bash eytdeploy
sudo usermod -aG docker eytdeploy
sudo install -d -o eytdeploy -g eytdeploy -m 750 /opt/eyt-erp
```

اگر کاربر یا مسیر از قبل وجود دارد، ابتدا وضعیت موجود را بررسی کنید؛ دستورات ایجاد را کورکورانه تکرار نکنید. عضویت در گروه `docker` عملاً دسترسی سطح root می‌دهد؛ این کاربر را فقط برای استقرار اختصاص دهید و کلید SSH آن را محدود و محافظت کنید.

## کلید SSH و میزبان مورداعتماد

1. یک جفت کلید SSH مخصوص استقرار بسازید؛ کلید خصوصی فقط در GitHub Environment Secret قرار می‌گیرد.
2. کلید عمومی را به `~eytdeploy/.ssh/authorized_keys` اضافه کنید و مجوزهای پوشه و فایل را درست تنظیم کنید.
3. کلید میزبان SSH را از کنسول/پنل معتبر ارائه‌دهنده یا مسیر مدیریتی مستقل تأیید کنید. صرف اجرای `ssh-keyscan` اتصال را معتبر نمی‌کند.
4. مقدار `DEPLOY_KNOWN_HOSTS` باید شامل سطر known_hosts برای همان میزبان تأییدشده باشد. برای پورت SSH غیر از 22 باید قالب `[host]:port` استفاده شود؛ workflow فعلی فقط نام میزبان/IPv4 و پورت پیش‌فرض را می‌پذیرد.

## DNS و HTTPS

رکوردهای زیر را در DNS به IP عمومی VPS اشاره دهید، بدون اینکه دامنه اصلی سایت را جابه‌جا کنید:

- `api.eytparts.ir` → IP عمومی VPS
- `app.eytparts.ir` → IP عمومی VPS

پس از تأیید انتشار DNS و باز بودن پورت‌های 80 و 443، reverse proxy و گواهی TLS را روی VPS راه‌اندازی کنید. چون Compose سرویس API را روی `127.0.0.1:8000` و کاتالوگ را روی `127.0.0.1:8080` منتشر می‌کند، reverse proxy باید به همین مقصدهای محلی وصل شود. نمونه Caddyfile:

```caddy
api.eytparts.ir {
    reverse_proxy 127.0.0.1:8000
}

app.eytparts.ir {
    reverse_proxy 127.0.0.1:8080
}
```

Caddy را فقط پس از نصب و تنظیم سرویس آن روی میزبان اجرا کنید. DNS و HTTPS در workflow استقرار ERP خودکار پیکربندی نمی‌شوند و باید جداگانه آزموده شوند.

## GitHub Environment secrets

در مخزن GitHub به مسیر **Settings → Environments → production → Environment secrets** بروید و این مقادیر را تنظیم کنید:

- `DEPLOY_HOST`: نام میزبان یا IPv4 VPS
- `DEPLOY_USER`: `eytdeploy` یا کاربر استقرار انتخاب‌شده
- `DEPLOY_SSH_KEY`: کلید خصوصی SSH استقرار
- `DEPLOY_KNOWN_HOSTS`: سطر میزبان SSH که مستقل تأیید شده است
- `DEPLOY_PATH`: `/opt/eyt-erp`
- `POSTGRES_PASSWORD`
- `JWT_SECRET`
- `BOOTSTRAP_SECRET`
- `RUBIKA_WORKSHOP_WEBHOOK_SECRET`
- `N8N_ENCRYPTION_KEY`
- `EYT_ERP_CHANNEL_TOKEN`

شش مقدار runtime آخر باید برای هر مورد مستقل، حداقل 32 نویسه و فقط شامل حروف انگلیسی، رقم، زیرخط یا خط تیره باشند. از یک مقدار برای چند secret استفاده نکنید. کلیدهای SSH، رمزها و secretها را در Git، issue، پیام یا فایل قابل‌عموم منتشر نکنید. مقدارهای واقعی را در log یا اسکرین‌شات قرار ندهید.

## اجرای استقرار

1. ابتدا همه پیش‌نیازهای بالا، DNS، HTTPS و مجوزهای فایل را تأیید کنید.
2. در GitHub وارد **Actions → E.Y.T Production Deploy → Run workflow** شوید.
3. اجرای workflow را فقط پس از بررسی مقادیر Environment و مقصد VPS آغاز کنید.
4. workflow فایل `.env.production` را با مجوز محدود منتقل می‌کند، Compose را اجرا می‌کند و منتظر `http://127.0.0.1:8000/ready` می‌ماند.
5. نتیجه سبز workflow به‌تنهایی آزمون DNS/TLS، بازیابی backup یا تراکنش واقعی کسب‌وکار را اثبات نمی‌کند.

## گیت‌های لازم پیش از GO

- [ ] `/health` و `/ready` پاسخ موفق می‌دهند.
- [ ] `https://api.eytparts.ir/health` و `https://app.eytparts.ir` از اینترنت قابل دسترسی و TLS معتبر دارند.
- [ ] ورود کاربر و مجوزهای RBAC آزموده شده‌اند.
- [ ] migrationها روی دیتابیس خالی و نسخه ارتقایافته در محیط آزمایشی بررسی شده‌اند.
- [ ] PostgreSQL از اینترنت قابل دسترسی نیست.
- [ ] backup گرفته و بازیابی آن در محیط جداگانه عملاً آزموده شده است.
- [ ] سناریوی آزمایشی دریافت، موجودی، تولید/WIP، QC، محصول نهایی، سفارش/فروش، فاکتور و وصول با داده آزمایشی به انتها رسیده است.
- [ ] اطلاعات واقعی مشتری، قیمت، BOM و موجودی فقط پس از تطبیق و تأیید وارد شده‌اند.
- [ ] هیچ قیمت تمام‌شده نامشخصی به‌صورت صفر یا حدسی برای تصمیم مالی تولیدی استفاده نمی‌شود.

تا زمانی که همه گیت‌های حیاتی مستند نشده‌اند، وضعیت انتشار **NO-GO** باقی می‌ماند. هیچ‌یک از موارد بالا نباید صرفاً به‌دلیل وجود کد یا workflow، انجام‌شده علامت‌گذاری شود.
